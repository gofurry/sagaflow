# Project Brief

## 一句话说明

SagaFlow 是一个本地优先的个人 AI 漫剧生产工作台，把项目、剧本、资产、模型生成、分镜画布和媒体处理放在一个可便携的数据目录与单一内核中。

## 目标用户

- 在 Windows、Linux、macOS、NAS 或小型服务器上独立创作的个人用户。
- 希望自己管理模型密钥、素材主副本和生成记录的创作者。
- 需要浏览器工作台，也希望桌面启动器降低启动、备份和本机工具管理成本的用户。

## 产品原则

1. **本地优先**：项目文件和素材先落本机，云服务是生成能力或可选副本。
2. **单进程闭环**：API、队列和 Worker 同进程运行，但任务状态持久化到 SQLite。
3. **显式外发**：只有用户选择发布到 S3 或调用云模型时，数据才离开本机。
4. **模型中立**：Prompt、音色和业务资产不绑定单一厂商；模型差异由目录和 adapter 表达。
5. **桌面壳轻量**：Fyne 只管理内核、日志、备份、FFmpeg、模型目录和帮助入口。
6. **可迁移**：数据目录与备份应允许用户带走完整项目，而不是锁在某个云端账户。

## 明确非目标

- 团队账号、邀请、角色权限、工作组和多人实时协作。
- Redis/PostgreSQL/消息中间件等强制外部基础设施。
- 把 S3 作为默认或唯一素材存储。
- 在启动器中复制完整工作台页面。
- 把厂商密钥、开发凭证或 FFmpeg 二进制写入开源仓库。

## 运行形态

### 内核版

`sagaflow[.exe]` 运行 CLI、HTTP 服务和后台任务，适用于服务器、Docker、NAS 或熟悉命令行的用户。

### 桌面版

平台入口启动 Fyne UI，内核藏在发行包内部目录。启动器通过健康检查与运行时文件连接内核，默认端口为 `18848`。

### Docker

镜像只包含内核与内嵌前端，不包含 Fyne 或 FFmpeg。数据通过 `/data` 卷持久化。

## 用户数据心智模型

```text
data/
├── sagaflow.db       元数据、队列、目录、调用记录
├── projects/         按项目组织、可被用户直接拿走的文件
├── objects/          兼容或共享内容对象
├── secrets/          本机凭证主密钥
├── temp/             可清理临时文件
├── backups/          备份归档
├── logs/             轮转日志
├── tools/            按需安装的 FFmpeg 等工具
└── catalog/          可选模型目录更新包
```

实际路径由 `internal/config` 和 `internal/platform/storage` 决定。修改存储布局时必须兼容已有数据，并同步备份、文件打开、下载命名和迁移逻辑。

## 发布基线

- 源码许可证：`AGPL-3.0-only`。
- Release 由 `v*` tag 触发 GitHub Actions 自动创建或补充资产。
- 核心包与桌面包覆盖 Windows/Linux/macOS 的 amd64/arm64。
- GHCR Docker 镜像覆盖 linux/amd64、linux/arm64。
- `model-catalog.json` 和 `SHA256SUMS` 是正式 Release 辅助资产。

不要在本文件维护具体最新版本号；以 Git tag、`Makefile`、workflow 输入和发布页面为准。
